# PagedOut SRE Incident Dataset

Real-world SRE incident postmortems scraped from public engineering sources and formatted for instruction fine-tuning on root cause analysis.

> **Status: data only.** The dataset is built. No model has been fine-tuned on it — there is no training script in this repository yet. See [Intended use](#intended-use).

---

## Dataset Overview

| Property | Value |
|----------|-------|
| Total Examples | **128** |
| Train / Test | 102 / 26 (80/20, fixed seed) |
| Format | Alpaca instruction format (JSONL) |
| Task | Root cause analysis from incident signals |
| Avg. input length | 1,410 chars |
| Avg. output length | 1,247 chars |

Generated by `processor/dataset_processor.py`; counts verifiable in `processed/dataset_stats.json`.

---

## Sources

| Source | Count |
|--------|-------|
| [danluu/post-mortems](https://github.com/danluu/post-mortems) | 128 (100%) |

Every record in the current dataset comes from the danluu collection, which itself aggregates postmortems from many engineering organizations — the individual origin blog for each record is preserved in `metadata.url`.

Broadening collection to additional first-party sources (Cloudflare, AWS, Google SRE Book, Netflix) is planned but **not yet implemented**; the scraper currently targets danluu only.

---

## Data Collection Process

### Step 1 — Scraping
`scraper/github_scraper.py` fetches postmortem links from danluu/post-mortems, scrapes each URL, extracts clean text content, and classifies incident type using keyword matching.

### Step 2 — Processing
`processor/dataset_processor.py` filters low quality records, formats each postmortem into Alpaca instruction format, and splits into train/test sets with a fixed random seed for reproducibility.

### Step 3 — Quality Filtering
Records are filtered out if:
- Raw text is less than 300 characters
- No title available
- URL is inaccessible

## Data Format

Each example follows the Alpaca instruction format:

```json
{
  "instruction": "You are an expert SRE engineer. Analyze the following incident report and provide a structured root cause analysis with remediation steps.",
  "input": "Incident Title: ...\nSeverity: P1\nIncident Type: database_connection_exhaustion\n\nIncident Summary:\n...\n\nRaw Incident Text:\n...",
  "output": "Root Cause Analysis:\n...\n\nCustomer Impact:\n...\n\nRemediation Steps:\n...\n\nPrevention:\n...",
  "metadata": {
    "id": "pm_0001",
    "source": "danluu/post-mortems",
    "url": "https://...",
    "incident_type": "database_connection_exhaustion",
    "severity": "P1"
  }
}
```

## Actual Distribution

Incident type is assigned by **keyword matching**, not human labelling. The distribution is uneven and a large share is unclassified — worth knowing before training on it.

| Incident Type | Count |
|--------------|-------|
| unknown | 38 |
| deployment_failure | 32 |
| high_latency_spike | 21 |
| memory_leak | 14 |
| network_partition | 12 |
| cascade_failure | 5 |
| disk_space_critical | 3 |
| cpu_throttling | 2 |
| database_connection_exhaustion | 1 |

| Severity | Count |
|----------|-------|
| P1 | 115 |
| P3 | 9 |
| P2 | 4 |

### Known limitations

- **30% unclassified.** 38 of 128 records fall through the keyword matcher as `unknown`.
- **Severity is near-constant.** 90% of records are labelled P1, so severity carries almost no signal.
- **Long-tail types are unusable.** `database_connection_exhaustion` has a single example, `cpu_throttling` two.
- **Outputs are extracted, not authored.** The `output` field is derived from the source text rather than written as a gold-standard analysis.
- **128 examples is small** for instruction tuning; expect this to need expansion before it produces a usable adapter.

## Intended use

This dataset was collected to fine-tune a small open model on SRE root cause analysis and benchmark it against a baseline. **None of that has been done yet.** There is no training script, no adapter, and no benchmark results in this repository. Any evaluation methodology and any comparison numbers would be written after that work exists, not before.

## Reproducing the Dataset

```bash
# Install dependencies
pip install -r requirements.txt

# Step 1: Scrape raw postmortems
python finetuning/dataset/scraper/github_scraper.py

# Step 2: Process into training format
python finetuning/dataset/processor/dataset_processor.py

# Output files
# finetuning/dataset/raw/postmortems_raw.jsonl
# finetuning/dataset/processed/train.jsonl
# finetuning/dataset/processed/test.jsonl
# finetuning/dataset/processed/dataset_stats.json
```
